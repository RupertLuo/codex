# 从 Catalyst Runtime 消费视角理解 Fork

## 1. 首轮盘点结论与证据范围

核对日期：2026-09-08。官方 `rust-v0.149.0` = `758ef40f50c1a458425c7cfbf1eb12cbc07af0b0`；fork 源码快照 = `a8e2b02ddb7d1ea07b1284631c8404e2c6380fcf`；Runtime 源码快照 = `2e04f40e1908f3bc1c657aad9565161983ebdf31`。两仓开始首轮检查时工作树干净。首轮仅修改 fork 治理文档；后续代码治理见第 8 节，不代表运行中制品或 Release lock 已使用这组源码。

架构方向可保留：Runtime 拥有产品能力，fork 暴露注入接口，上游继续拥有执行、会话和存储生命周期。主要治理风险是默认行为补丁没有与 opt-in 接口分开、少数核心路径承担多种补丁、测试入口被误当作完整验收证据。当前不具备“所有 Cata 测试完备”的结论。

首轮证据包括本地 tag/commit、完整文件差异统计、Rust manifest、两条装配链、重点实现和测试源码。未运行 Rust 测试、编译、GUI、真实 Provider 请求或 Windows 验证；未对全部 154 个文件逐行作安全审计。逐文件清单见[差异索引](04-官方基线差异索引.md)。

## 2. Java 架构师可以怎样理解

| Rust 对象 | 类比与实际责任 |
| --- | --- |
| crate / Cargo path dependency | 接近 Maven 多模块源码依赖；链接进宿主二进制，不是启动完整官方 CLI |
| `ThreadManagerRuntimeOptions` | 显式依赖注入装配对象；保存进程提供的能力，再传入 thread/session |
| `Arc<dyn Trait>` | 共享的接口实现引用；需要关注并发、生命周期与取消，不能当作独立业务服务 |
| `RuntimeExtension` / Skill provider | 工具及 Skill 接入接口；产品实现归 Runtime，注册和执行边界归 Codex |
| `AppServerProcessOverrides` | App Server 装配层；除 ThreadManager 外还承接 RPC 与进程 MCP 配置 |
| `Session` / `LiveThread` | 上游执行与持久化生命周期 owner；宿主不应复制另一套会话真相 |

Runtime 的 12 个 crate manifest 直接声明 82 条 Codex 路径依赖记录、27 个唯一 crate，包含 dev dependencies。声明在各 `crates/*/Cargo.toml`，不是根 manifest 的统一 dependency 表。`codex-app-server-client` 在 Runtime app-server 中是开发测试依赖，不能当作产品启动路径。

路径依赖会编译被消费的库代码，但不会自动运行依赖 crate 自身的测试。宿主测试通过与 fork 测试通过是两类证据。

## 3. 两条生产装配线

```text
Catalyst ProductRuntime
  ├─ catalyst-app-server::process_overrides
  │    → AppServerProcessOverrides → run_app_server_serve
  │    → ConfigManager / ThreadManager / RPC registry → Session
  └─ catalyst-codex::main
       → ThreadManagerRuntimeOptions + TuiRuntimeOptions
       → run_main_with_runtime_options → TUI / Session
```

以下 Runtime 路径均相对 Runtime 仓库根；fork 路径相对本仓库根。

| 能力 | App Server | TUI | 产品实现 owner |
| --- | --- | --- | --- |
| required instructions、HTTP、catalog、model policy | 注入 | 注入 | Runtime `crates/catalyst-codex/src/runtime.rs`、`model_catalog.rs` |
| search、market data、image generation、private Skill extensions/provider | 注入 | 注入 | Runtime 对应 `catalyst-tool-*`、`catalyst-private-skills` |
| Browser extension | 条件注入 | 当前 main 未注入 | Runtime Browser 能力 |
| thread activity、title generator、产品 RPC | 注入 | 当前 main 未注入 | Runtime app-server；title model/usage 归 Runtime |
| credential/readiness/onboarding UI | RPC 业务路径 | `CatalystTuiModelRuntime` | Runtime `tui_model_runtime.rs` |
| process MCP table replacement | 通过 flatten 的共享 CLI 接受 | 当前 TUI 装配未使用该入口 | fork CLI/config；调用者提供 server 表 |

精确入口：Runtime `crates/catalyst-app-server/src/lib.rs::process_overrides`、`src/main.rs`、`src/cli.rs`；`crates/catalyst-codex/src/main.rs`。共享 `ProductRuntime` 不代表最终工具集合相同。

## 4. 补丁能力账本

“默认变化”表示即便没有显式 override，fork 仍可能与官方不同。每一行是能力族，不代表单个提交或独立文件。

| 能力族 | 相对官方增加/改变什么 | 作用域及边界 | 合并重点 |
| --- | --- | --- | --- |
| 宿主 HTTP transport | `HttpTransportHandle`、Core client override；有 override 时不用模型 WebSocket | process 注入、session 消费；Provider 适配和凭据归 Runtime | Core client、session spawn、HTTP factory |
| catalog 与 model policy | 静态目录；HTTP 增量、图片迁移、请求 byte budget、并行工具能力覆盖 | 逐 model 策略；上游 `StaticModelsManager` 本身可复用，不是新造 catalog 引擎 | 新模型字段、模型切换、默认策略 |
| required instructions / prompt debug | 保留宿主基础指令并组合任务指令；使用同一 runtime options 生成 prompt snapshot | thread 创建；debug 不证明工具真实执行或权限闭环 | ThreadManager、prompt builder、恢复入口 |
| Runtime 工具扩展 | search/image gate、工具注册、受限图片输出提示 | extension 接口通用；Tavily、行情、图片服务实现均在 Runtime | `tools/spec_plan.rs`、extension registry；提示长度上限 |
| Skill provider | 按 authority/kind 路由，provider catalog/read 接入 | 显式 provider 注入；解密/授权不进入 fork | sources/catalog/tools 与宿主 entitlement |
| Skill roots 限制 | 不再自动发现用户及项目 `.agents/skills`；配置层、plugin、extra roots 仍保留 | **默认变化**，不由 runtime options 开关控制 | 上游 discovery 更新；不能整体恢复旧扫描逻辑 |
| RPC/native gateway | namespaced 产品方法；复用 native plugin list/turn start | process 注册；initialize、transport context、thread queue/session gate | `message_processor.rs`、plugin processors |
| process MCP 配置 | `--process-mcp-server` 替换指定 server 整表；其他 server 保留，rebuild 继续应用 | process config 接口；不是 ThreadManager option，也不是全局文件修改 | precedence、相对路径、refresh/rebuild、原配置约束 |
| 自动标题及事件 | 可注入 generator；持久化成功后通知；手工标题优先 | store 中异步任务；Core session 自建 metadata mutation gate | `LiveThread`、shutdown、`ThreadNameUpdated` 协议适配 |
| 流式 item 归属 | SSE 保留 item ID，交错 item 的 delta 按 ID 路由；提前文本 delta 缓冲 | **默认变化**，作用于响应流；无 ID 仍有 active-item 兼容路径 | SSE → ResponseEvent → sampling → 对外 item event |
| TUI 产品接入 | catalog picker、credential secret 输入、onboarding/readiness | 抽象 `TuiModelRuntime`；产品 Provider 业务在 Runtime | startup、event dispatch、submission、snapshots |
| Windows private desktop | 同账户/等价权限复用隔离 desktop，跨 runner/ConPTY 传递 | **平台默认执行变化**；不属于 Provider 注入 | desktop cache key、ACL、elevated/legacy 启动全链 |
| HTTP client / 构建适配 | login 暴露 raw reqwest client；依赖/穷举 event match 随之变化 | API 适配与编译输入；不是独立产品功能 | custom CA/client policy、Cargo/Bazel 双构建一致性 |

Core 的 byte budget 是历史大小估算与 4/5 阈值触发预采样压缩，不是精确序列化 body 上限。图片重编码和 Provider 协议转换仍在 Runtime；fork 图片迁移当前仅处理 `FunctionCallOutput`，不能泛称所有 tool output 都支持。

## 6. 治理顺序与完成标准

本轮完成文档基线和可追踪边界；以下是后续独立工作包，不是已修复或当前生产故障：

1. **先补关键接入契约测试**：fork RPC registry/initialize/native queue 与 process MCP reload。以公开入口行为断言为准，避免只测 helper；不改变既有产品权限语义。
2. **再闭合 Provider 请求契约**：图片迁移、baseline、失效回退、byte-budget，并核对宿主实际 policy/output 到 Core 请求；避免 live probe 代替确定性测试。
3. **补两条装配契约**：App Server/TUI 的实际工具集合和 catalog/readiness 分别验证；保留它们已存在的产品差异，不为了对称而加功能。
4. **随后改善核心可读性**：优先把 `client.rs` 的请求变换/增量状态、`turn.rs` 的 item 归属作为独立模块候选；复用上游生命周期，先有行为测试再移动代码。不要仅为减少单文件行数重写整个 core。
5. **每次上游升级做删除评估**：逐能力比较新官方是否等价，保留最小接口；默认行为变化和 Windows patch 单独验收。跟随新 tag 原样更新 `AGENTS.origin.md`。

每个工作包完成标准：可定位的宿主 consumer、明确默认/作用域、聚焦行为测试通过、无新增 authority/兼容性改变；需要新产品决策的改动另行裁决。同步验收沿用[上游同步手册](02-上游同步手册.md)，不要求每次运行整个官方测试套件。

## 7. 文档与构建方面的剩余边界

- `AGENTS.origin.md` 已逐字匹配官方 tag 的根 AGENTS；本轮完善的是 Catalyst 专属入口及验证覆盖规则。
- 旧文档声称 `docs/` 完全原版，但快照存在两份新增 `docs/superpowers/plans/2026-08-30-*.md`。这是历史文档偏离，不是产品 patch；本轮保留路径，未审阅或搬迁其内容，避免未经核对破坏历史引用。
- `Cargo.lock` 的大量 package version 变化及 reqwest/zeroize 依赖必须与行为补丁分开评估；当前没有执行 Bazel lock 或 schema 生成，不能给出双构建/生成物一致性资格。
- 首轮未修改 Runtime、Workbench、release pin 或 Rust 源码，也未提交 Git。架构盘点完成不等于所有后续治理工作包已完成。

两个仓库均在 `feat/yanjiang`，本批建立在上述源码快照和首轮文档改动之上。

- 原生 `web.run` 与 `image_gen.imagegen` 保持原有 gate；产品工具 wire 名称、公开历史常量值不变。生图旧断言曾错误描述为 Core 按产品名判定，已修正；Runtime 历史回放仍可使用兼容常量。
- Qwen 回退矩阵新增 `image_baseline_404`：验证图片-only、混合文字、多图顺序、完整回退和恢复后的继续增量。Provider 策略、Core 增量状态机本批未改。
- Core 保存 typed baseline，Runtime 随后稳定转换成最终请求。该用例覆盖合成历史图片，不证明真实工具执行、大图重编码或未 Completed 流恢复。
- 产品 RPC 继续走原 registry/native turn gateway；崩溃编排仍归宿主；未开启 OpenAI 增量，也未增加产品权限或新的 Turn 生命周期。
