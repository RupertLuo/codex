# 模块边界与代码识别

本 fork 由三层组成：官方执行引擎、为 Catalyst 保留的宿主接入契约、Runtime 中的产品实现。**契约由 fork 提供，不代表产品实现应留在 fork。**

## 从目录和注释识别来源

| 代码形态 | 如何识别 | 维护方式 |
| --- | --- | --- |
| 独立宿主适配 | 已分离的模块位于所属 owner 的 `catalyst/` 目录；其他既有独立模块带 `//! CATALYST:` 说明 | 实现和直接测试放在一起，接口仍按职责命名 |
| 原生模块中的宿主接入 | 接入点旁的 `CATALYST` 注释说明注入内容和原生 owner | 保留原生文件、控制流、权限和状态；不要把整个混合文件归为 Cata |
| 上游已有代码 | 对照 `rust-v0.153.4` 的 Git diff 确认 | 升级时优先接入上游变化，不给原生函数统一加产品前缀 |
| 产品实现 | Runtime 仓库的 `crates/catalyst-*` | Provider、凭据、产品 RPC、私有 Skill 与具体工具实现由 Runtime 负责 |

注释是阅读入口，不是完整逐行归属清单。未标记不代表未修改；新增文件也可能包含从原生模块提取的代码，例如 `app-server/src/cli.rs`。具体文件的准确差异使用 `git diff rust-v0.153.4 -- <path>`，盘点移动时使用 `git diff --find-renames`。

## 已分开的两个核心边界

```text
core/src/client.rs                         原生模型请求/恢复编排与宿主接入点
└── client/catalyst/
    ├── model_policy.rs                   宿主策略数据契约
    ├── host_http.rs                      图片迁移、失效识别纯函数
    └── host_http_tests.rs                直接测试

app-server/src/lib.rs                      原生服务装配与 process overrides
app-server/src/message_processor.rs        原生分发、initialize、Turn/plugin gateway
app-server/src/config_manager.rs           原生配置加载与 process replacement 接入
└── catalyst/
    ├── rpc_extension.rs                  注册/冲突检查、宿主 RPC 契约
    ├── rpc_extension_tests.rs             注册表行为
    ├── message_processor_rpc_tests.rs     原生分发入口的宿主契约测试
    └── config_manager_tests.rs            process replacement 配置测试
```

采用 `#[path]` 指向物理目录，Rust 逻辑模块保持不变，因此 `crate::rpc_extension`、原有测试完整名称以及 Runtime 使用的公开 re-export 不变。`ModelRuntimePolicy` 继续从 `codex_core::client` 导出。这两个边界的模块搬迁不改变 Runtime import；敏感值基础 crate 的新增依赖另见下节。Bazel 现有 `src/**/*.rs` 收集这些模块；不要在子目录加新的 `BUILD.bazel` 形成独立 package。

HTTP baseline 是 fork 增加的状态，但仍由原来的 ModelClient 持有。图片纯函数可以拆出，baseline 的消费、成功更新和失败恢复必须留在请求编排中。RPC 模块可以独立，initialize 门禁和原生 Turn 执行必须继续由 MessageProcessor 负责。

## 按职责导航其他边界

下表中“接入点”是混合模块，“契约/适配”标识独立宿主部分；按原 owner 保留混合接入点。

| 能力 | Fork 契约/适配 | 原生接入点与职责 | Runtime owner |
| --- | --- | --- | --- |
| 进程/线程装配 | `core/src/thread_manager.rs::ThreadManagerRuntimeOptions` | ThreadManager 创建和管理原生 thread | `catalyst-codex` 装配，`catalyst-app-server` 启动 |
| 模型 HTTP | `codex-client/src/transport_handle.rs`、`client/catalyst/model_policy.rs` | `core/src/client.rs` 管理请求、baseline、重试；Guardian 不消费 HTTP 增量 baseline | Provider policy、transport、wire 转换 |
| 工具规划 | `tools/src/tool_executor.rs` 的独立搜索能力声明 | `core/src/tools/spec_plan.rs` 保留注册结果与原生 gate | `catalyst-tool-*` 实现 |
| RPC | `app-server/src/catalyst/rpc_extension.rs` | `message_processor.rs` 原生生命周期及 method 冲突隔离 | 产品 RPC handler |
| Skill/MCP | `ext/skills/src/sources.rs` 的宿主 source 接口 | Skill authority 路由、根合并、预算和原生配置 owner | `catalyst-private-skills` 及宿主 MCP 配置 |
| 标题 | `thread-store/src/title_generator.rs` | thread store 保存标题和历史 | 宿主 title generator |
| 敏感值基础类型 | `utils/sensitive-string/src/lib.rs::SensitiveString` | TUI 保留 `SensitiveInput` 兼容导出；基础类型负责脱敏和零化 | credentials、Provider、搜索直接依赖基础 crate |
| TUI | `tui/src/catalyst/model_runtime.rs`、`chatwidget/credential_popups.rs`、`bottom_pane/sensitive_prompt_view.rs` | ChatWidget 模型 readiness、既有 popup 和事件流程 | `catalyst-codex` 的 model runtime |
| 图片上下文 | `core/src/context/image_generation_instructions.rs` | 原生 context/history owner；请求迁移不改写持久化历史 | `catalyst-tool-image-gen` |

其他流式 item、历史格式等已有差异继续按 [Patch 地图](01-Patch地图.md) 审查，不能因这次模块整理而视为已全部重构或验证。

## 敏感值和 TUI 契约分层

`SensitiveString` 归 `codex-utils-sensitive-string`，不依赖 TUI 或 Runtime。`tui/src/catalyst/credentials.rs` 定义凭据展示数据，`model_runtime.rs` 定义宿主交互契约；旧 `codex_tui::SensitiveInput` 作为同类型兼容导出保留。Runtime 的 `tui_model_runtime.rs` 只做领域结果到 TUI 契约的转换，直接测试移到同目录 `tui_model_runtime_tests.rs`。详见 [分层设计与验收](08-敏感值分层与Cata测试设计.md)。

版本适配与模块治理的执行证据集中在[升级记录](06-0.153.4升级验证.md)和[分层验证](08-敏感值分层与Cata测试设计.md)，避免将阶段性记录当作当前全量测试结论。
