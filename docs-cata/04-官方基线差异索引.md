## 三、文件归属判断

看到差异时按以下顺序判断：

1. 官方基线是否已经有相同能力？
2. 这处变化是宿主契约、上游 API 适配，还是测试/生成结果？
3. 哪个运行时消费者会失败？
4. 是否有 focused test、wire body、schema 或 snapshot 证明必须保留？
5. 新上游是否已经提供更小、更稳定的 boundary？

推荐结论标签：`retained patch`、`adaptation`、`upstream equivalent`、`test/generated`、`infrastructure`、`needs review`。

## 四、机器可读检查

```bash
git diff --stat rust-v0.149.0..HEAD
git diff --name-status rust-v0.149.0..HEAD -- codex-rs/
git diff --name-status rust-v0.149.0..HEAD -- '*.rs'
git diff --name-status rust-v0.149.0..HEAD -- '*.md'
git diff --check
```

官方文档目录应保持原版，不因 fork 文档整理而加入 Catalyst 内容：

```bash
git diff --quiet rust-v0.149.0..HEAD -- docs/
```

该命令只适合检查相对官方基线的状态；若基线自身更新，需先确认目标 release 的官方文档变化，再判断是否为本 fork 改动。
